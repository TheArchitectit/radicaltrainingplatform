# Virtualization and Cloud Computing (A4)

*Module A4 — CompTIA A+ Core 1 study track. Independent study material — see the disclaimer at the end.*

Everything in A3 assumed one operating system per machine. This module removes that
assumption. Virtualization puts several operating systems on one computer; cloud computing
rents someone else's computers over a network. They are related but different ideas, and
the exam asks you to keep them apart: one is a technique for using hardware you own, the
other is a way of buying capacity you do not.

## Virtualization: what it is and why it exists

A **virtual machine (VM)** is a complete pretend computer — CPU, memory, disk, network —
created in software. The software that creates and runs it is the **hypervisor**, and the
physical machine underneath is the **host**; each VM is a **guest**. The guest sees
hardware that looks normal and installs an ordinary operating system.

The reasons are mostly economic and practical:

- **Server consolidation.** A physical server that spends its life at 10% utilization
  becomes one of ten VMs on a host that is actually busy.
- **Isolation.** A crash or compromise inside one VM does not automatically reach the
  others, and a test VM can be destroyed and recreated at will.
- **Snapshots.** A **snapshot** captures a VM's state at a moment so it can be rolled back
  — the fastest undo button in computing, and not a backup.
- **Legacy and cross-platform software.** An old application that only runs on an older
  operating system gets its own VM instead of its own machine.
- **Development and testing.** Build a clean environment, test the installer, throw it
  away.

Two hypervisor types, and the distinction is exam material:

- **Type 1 (bare metal).** The hypervisor runs directly on the hardware; the guest
  operating systems sit above it. Used in data centers and on servers — faster, and the
  standard for production virtualization.
- **Type 2 (hosted).** The hypervisor runs as an application inside a normal desktop
  operating system. Convenient for a workstation that needs a test VM, at the cost of a
  layer of indirection.

**Containers** are the other half of the story. A container shares the host's kernel and
packages only the application and its dependencies. Containers start faster and are
lighter than VMs, but isolation is weaker because they share a kernel — which is exactly
the trade the exam wants you to name.

**Desktop virtualization** puts the desktop somewhere else. **VDI (virtual desktop
infrastructure)** runs each user's desktop as a VM in a data center; the user connects
from a thin client. The benefit is centralized management and data that never leaves the
data center; the cost is that the network becomes the computer.

**Resource requirements** do not disappear because the machine is virtual. Each VM needs
its own allocation of CPU cores, memory, disk and network, and the host must have enough
of all four for the guests it runs. Overcommitting memory is the classic cause of a
virtualization host that is "slow for no reason". **Virtual networking** adds its own
layer: each VM has a **virtual NIC**, the hypervisor runs a **virtual switch**, and the
host's physical NIC carries the traffic — so a VM's connectivity problem may be a
virtual-switch setting, not anything physical.

One licensing note worth remembering: a virtual machine still needs a license for its
guest operating system, and some desktop operating systems have rules about where they may
be virtualized. A VM is not a way around licensing; it is a way around buying another
computer.

## Cloud computing: the same idea, rented

Cloud computing delivers computing resources over a network, on demand, with the provider
owning the hardware. The exam tests three things: the service model, the deployment model,
and the characteristics that make something "cloud" rather than "a server somewhere".

**Service models**, from most to least that you manage:

- **IaaS (infrastructure as a service).** The provider gives you virtual machines,
  storage and networking; you install and manage the operating system and everything
  above it. Maximum control, maximum responsibility.
- **PaaS (platform as a service).** The provider gives you a runtime and the platform
  underneath it; you deploy your application and data. You do not patch the operating
  system.
- **SaaS (software as a service).** The provider runs a finished application you use
  through a browser or client. You manage your data and your users, and nothing else.

**Deployment models:** **public** cloud is shared provider infrastructure available to
anyone; **private** cloud is dedicated to one organization, on or off its own premises;
**hybrid** combines the two with some integration between them. The word to recognize in
questions is ownership and tenancy, not location — a private cloud can be hosted.

**The five characteristics** that define cloud computing: on-demand self-service,
broad network access, resource pooling, rapid elasticity, and measured service. Reading
them as sentences explains the appeal: you provision without a purchase order, you reach
it from anywhere, you share hardware, you grow and shrink quickly, and you pay for what
you used.

**The shared responsibility model** is the practical consequence: the provider secures the
facility, the hardware, and the platform layers it owns; you secure what you put on top —
accounts, data, configuration. A breached storage bucket in the cloud is almost always a
customer-side configuration failure, and knowing which side owns which control is the
skill being tested.

**What cloud means for a technician:** an internet connection becomes a dependency, so
offline work and local caching matter; **cloud storage** (file sync, object storage,
backup) is not the same as a network drive; and **cloud-based productivity tools** move
documents from local disks to shared services, which changes where the data is and who
can reach it. **Virtualization** is what makes all of this possible underneath — the
provider's data center is a large number of VMs, and your company's private cloud is
probably one too.
