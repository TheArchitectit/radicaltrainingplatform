# Networking Basics (A2)

*Module A2 — CompTIA A+ Core 1 study track. Independent study material — see the disclaimer at the end.*

Every device that joins a network has to know a few things about itself and about the network around it. This lesson covers the four settings every host needs, what DHCP and DNS actually do for you, how ports work, and the SOHO Wi-Fi basics you will see in the field. When you finish, you should be able to read a workstation's network configuration panel and spot the field that is wrong.

## The four things every host needs

For a host to take part in an IPv4 network, four settings must be correct:

1. **IP address** — the host's own address on the network. Without it, the host has no identity and cannot send or receive anything.
2. **Subnet mask** — tells the host which part of the address is the network and which part is the host. The mask is how the host decides whether a destination is *local* ("same street") or *remote* ("another town, send it to the router").
3. **Default gateway** — the router's address on the local network. Any destination the host decides is remote goes to the gateway. If the gateway is wrong or missing, the classic symptom is: you can reach devices on your own network, but nothing outside it.
4. **DNS server** — the address of the service that turns names like `www.example.com` into IP addresses. Without it, anything you reach *by name* fails, even though the network itself may be fine.

All four come as a set. If any one of them is wrong, you get a different and quite recognizable failure pattern — which is exactly what the troubleshooting modules build on.

## What DHCP hands out — and what breaks without it

Typing those four settings by hand on every device would be slow and error-prone. **DHCP (Dynamic Host Configuration Protocol)** does it automatically. When a device joins the network, it asks, and a DHCP server hands it a *lease*: an IP address to use, the subnet mask, the default gateway, and the DNS server address, plus a time limit after which the lease must be renewed.

What DHCP hands out is therefore exactly the four settings above — that is not a coincidence, it is the design.

When DHCP *fails*, the failure depends on what the device does next. Many operating systems fall back to an **APIPA** address — an address in the `169.254.x.x` range that lets the device talk to other devices on the same local segment and nothing more. So the symptom of a DHCP problem is very specific: the device can sometimes reach its immediate neighbors but has no gateway and no DNS, so nothing beyond the local network works. If a user says "my machine has an address starting with 169.254," you are almost certainly looking at a DHCP delivery failure, not a broken application.

## What DNS translates — and the classic symptom

**DNS (Domain Name System)** is the internet's phone book. It translates names — `www.example.com` — into IP addresses, because people remember names and networks move packets by address.

The classic DNS failure has a famous signature: **"it works by IP address but not by name."** If typing `http://93.184.216.34` reaches the site but typing `http://example.com` does not, the network path is fine — packets flow, the server answers. The only thing missing is the translation step. That points at DNS: a wrong DNS server setting, a DNS service that is down, or a name that does not resolve.

Learn this symptom well. It is one of the most useful one-line diagnoses in beginning networking, because it cleanly separates "the network is broken" (both name and IP fail) from "the name lookup is broken" (IP works, name fails).

## Ports: doors for services

An IP address gets your packets to the right *machine*. A **port** gets them to the right *service* on that machine — one machine can run a web server, a mail server, and a file transfer service at the same time, and ports are how the traffic is sorted.

You do not need to memorize the full port list at this stage. Three examples cover a huge share of real traffic:

- **80** — HTTP, ordinary web traffic
- **443** — HTTPS, encrypted web traffic (the padlock in your browser)
- **53** — DNS, name lookups

Think of ports as numbered doors on the same building: the address gets you to the building, the port says which office you want.

## SOHO Wi-Fi basics

A small office or home network usually runs on a single wireless router. Four concepts matter:

- **SSID** — the network's name, the one you pick from the list of available networks. Broadcasting it makes joining easy; hiding it is a weak security measure at best, since the name still appears in traffic.
- **Passphrase** — the Wi-Fi password. Modern networks use WPA2 or WPA3; the passphrase protects joining, not the traffic after joining.
- **2.4 GHz vs 5 GHz** — the 2.4 GHz band travels farther and penetrates walls better but is slower and more crowded (microwave ovens, neighbors, Bluetooth all live here). The 5 GHz band is faster and cleaner but has shorter range. Dual-band routers offer both, often under two SSIDs.
- **Guest networks** — a separate network for visitors so their devices do not touch yours.

## Reading a configuration panel

Given everything above, a workstation's IPv4 configuration panel should now read like a sentence: *this is my address (IP), this is how I tell local from remote (mask), this is where I send everything else (gateway), and this is who translates names for me (DNS)*. The practice set for this module asks you to find the one field in that sentence that is wrong.
