# Software Troubleshooting (B3)

*Module B3 — CompTIA A+ Core 2 study track. Independent study material — see the disclaimer at the end.*

Hardware faults announce themselves. Software faults argue. A machine that boots to a blue
screen, an application that closes itself, a phone that eats battery, a browser that
redirects every search — the exam calls these software troubleshooting, and the method is
the one from A5: identify, theorize, test, plan, verify, document. What changes is the
evidence you collect, because the evidence is now logs, settings and behavior rather than
lights and sounds.

## Windows operating system issues

Group the symptoms by when they happen, and the diagnosis gets much shorter.

**It will not boot.** A **blue screen (BSOD)** at startup gives you a stop code — read it
before anything else, because it usually names the failing component. **Startup Repair**
and the **Windows Recovery Environment** are the first tools; **safe mode** boots with a
minimal driver set, which tells you whether a driver or a startup program is the cause.
`bootrec`, `sfc /scannow`, and `chkdsk` repair the boot configuration, the system files,
and the disk in that order. If the disk is failing, repair is a detour: image the data
first.

**It boots, but slowly.** The usual suspects in order: too many **startup programs**
(Task Manager's Startup tab shows their impact), a nearly full system drive, failing
storage, insufficient memory, malware, and a machine that is thermally throttling. Measure
before changing anything — a boot-time number before and after is the only proof you fixed
it.

**Applications crash, hang, or will not install.** Check the architecture (32-bit
application on a 64-bit OS is fine; the reverse is not), the OS version, permissions, disk
space, and whether the application needs a runtime or a driver that is missing. **Event
Viewer** turns "it just closes" into an error code and a module name.

**The profile is wrong.** A **temporary profile** at logon — the desktop is empty and the
documents are gone — means the user profile could not load. The data is normally still on
disk; do not delete the profile before copying it out.

**Updates fail.** Check free disk space, the time and the update service, and the error
code. Repeated failures on one machine usually trace to corrupted update components or
third-party software blocking the change.

**Drives disconnect, printers stop, the clock drifts.** Mapped drives that drop are often
the network profile or the credential; a stuck print queue blocks every job behind it; a
machine whose clock is minutes off will fail certificate checks and domain logons, and a
dead **CMOS battery** is the usual cause on an older desktop.

## Mobile operating system and application issues

The same three questions — what changed, what does it do, can I reproduce it — with the
mobile constraint that you often cannot see the logs.

**Application problems.** An application that crashes at launch, will not update, or
demands permissions it should not need is usually fixed by force-stopping it, clearing its
cache, reinstalling from the store, or checking that the OS version it needs is actually
installed. An application that will not install at all is often out of storage, or blocked
by a management profile.

**Storage and performance.** "Storage full" explains a remarkable share of mobile
misbehavior: applications cannot write, updates cannot install, and the camera stops. A
phone that is slow or hot while idle is usually one runaway application or a failing
battery, in that order.

**Connectivity and sync.** No cellular data, no Wi-Fi, Bluetooth that will not pair —
check the settings and airplane mode first, then the carrier or network, then hardware. A
phone that will not sync is usually an account credential, a full mailbox, or a management
profile that was never removed.

**Updates and lockouts.** An OS update that fails repeatedly needs free space and a
working network; a device that is locked out by too many passcode attempts may need the
management system or the vendor's recovery path, and a device that is wiped without a
backup is the one outcome to prevent before anything else.

**The mobile escalation ladder** is worth memorizing: restart, update the app and the OS,
clear cache, reinstall, reset settings, factory reset after a backup, then hardware. Each
step is more invasive than the last, which is why the order matters.

## PC security issues

A machine with malware usually tells you in its behavior before any scanner does:

- **Pop-ups and redirects** — a browser that opens windows or sends searches somewhere
  unexpected.
- **Slowdown and unexpected network traffic** — a machine that is busy when nobody is
  using it, or a network link that is saturated at night.
- **Security software disabled or missing** — malware that turns off the very thing meant
  to catch it.
- **Fake alerts** — a "virus detected, call this number" page is an attack, not a warning.
  Nothing legitimate asks you to phone a support line.
- **Changed settings** — a new home page, a new search provider, a toolbar nobody
  installed, a proxy setting you did not make.
- **Account and certificate warnings** — a locked account with no failed logons from the
  user, or certificate warnings that appear on one machine only.

The response is the B2 removal procedure: identify, quarantine, disable System Restore,
remediate, re-enable and create a clean restore point, update, rescan, and educate. For a
**browser hijack**, resetting the browser to defaults after removing the extension usually
does it. For a **rootkit**, or a machine whose trustworthiness is in doubt, **reimage** —
and if the machine handled sensitive data, treat it as an incident and preserve evidence
before wiping.

## The tools, in one list

**Task Manager** for what is running and what starts at boot; **Event Viewer** for what the
system recorded; **System Configuration (msconfig)** for startup and boot options;
**safe mode** for isolating drivers; **System Restore** for rolling back a change;
**`sfc /scannow`**, **`chkdsk`**, and **DISM** for repairing system files and images;
**Windows Update** and **Device Manager** for the platform itself; and the **reset this PC**
option when repair would take longer than reinstallation. Every one of these is a way to
replace a theory with evidence.
