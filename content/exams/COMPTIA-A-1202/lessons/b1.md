# Operating Systems and Configuration (B1)

*Module B1 — CompTIA A+ Core 2 study track. Independent study material — see the disclaimer at the end.*

Core 2 starts at the operating system, because almost every later fault is an operating
system fault once the hardware is ruled out. This lesson covers what an operating system
is and does, how to install and upgrade one, how Windows is organized, the command line
you will actually type, and the two other desktop operating systems the exam expects you
to recognize.

## OS types and what they are for

An operating system manages the hardware, provides the file system, schedules processes,
and presents a user interface. The types you need to recognize:

- **Workstation OS** — Windows, macOS, a Linux distribution. Interactive, one user at a
  time, optimized for applications and a screen.
- **Server OS** — the same technologies, tuned for services rather than a person: more
  concurrent connections, no local interactive workload, managed remotely.
- **Mobile OS** — iOS and Android. Sandboxed applications, aggressive power management,
  management through MDM rather than a local administrator.
- **Embedded OS** — inside a device that is not a computer: kiosk, point-of-sale terminal,
  network appliance. Often invisible, and rarely patched by its owner.
- **Virtualized and cloud OS** — the same operating systems running as guests (A4), where
  the hardware abstraction is a hypervisor and the "disk" is a virtual disk image.

The exam habit to build: read the scenario, decide the role (interactive desktop, shared
server, locked-down appliance), then pick the OS family that matches it.

## Installation and upgrade

A **clean install** erases the target and installs fresh: predictable, no accumulated
faults, and everything must be reconfigured. An **in-place upgrade** preserves files and
applications and replaces the OS: fast to the user, and it carries forward every problem
it started with. **Repair install** and **recovery partition** sit between the two — the
recovery environment exists so that a failed boot is fixable without media.

The mechanics the exam tests:

- **Boot methods.** Optical/DVD where still used, **USB** as the modern standard, **network
  boot (PXE)** for deploying many machines, and **internal drive** for imaging. Every one of
  them requires changing the boot order in **UEFI/BIOS**.
- **Partitioning and formatting.** Partition the disk, then format it with a file system.
  **GPT** is the modern partition scheme and is required for large disks and for UEFI
  Secure Boot; **MBR** is the legacy scheme with a 2 TB limit. Windows installs create a
  **system partition** as well as the OS partition.
- **File systems.** **NTFS** for Windows, with permissions, encryption and journaling;
  **exFAT** for removable media that must work across platforms; **FAT32** for maximum
  compatibility with a 4 GB file limit; **APFS** for macOS; **ext4** for Linux.
- **Driver installation.** Install the chipset, storage and network drivers from the
  vendor, not only what the OS found on its own. A missing network driver is why "the
  internet does not work after the install" is such a common ticket.
- **Post-install essentials.** Updates, a local account strategy, a backup tool, and a
  verified restore path.

## Windows editions and features

The edition determines what the machine is allowed to do. For the exam, the useful
distinction is: **Home** lacks domain join and some management features; **Pro** adds
domain join, BitLocker, Remote Desktop host, Hyper-V and Group Policy; **Enterprise**
adds volume licensing and the larger management and security feature set; **Education**
tracks Enterprise closely for schools. In practice, "the feature is missing" is often an
edition question before it is a fault.

The tools you navigate by:

- **Settings** — the modern interface for display, network, accounts, privacy, updates and
  time.
- **Control Panel** — the older interface, and still the only place for some settings.
- **Task Manager** — processes, performance, startup impact, users, services. The first
  place to look at a slow machine.
- **Device Manager** — every piece of hardware, its driver, and whether it is working.
- **Disk Management** — partitions, volumes, drive letters, and what is allocated.
- **Event Viewer** — the record of what the system says went wrong, split into
  application, security and system logs.
- **Task Scheduler, Services, Resource Monitor, Performance Monitor, System Configuration
  (msconfig), Registry Editor, Local Users and Groups, Group Policy Editor** — the
  administrative set; **MMC** is the shell that hosts most of them.
- **Windows Update** and the **Windows Recovery Environment** — patching and boot repair.

## The command line

Know each tool by the question it answers:

- **Configuration and testing:** `ipconfig` (and `/all`, `/release`, `/renew`, `/flushdns`),
  `ping`, `tracert`, `pathping`, `nslookup`, `netstat`, `net use`, `whoami`, `hostname`,
  `winver`.
- **File and directory work:** `dir`, `cd`, `md`, `rd`, `copy`, `xcopy`, `robocopy`,
  `del`, `move`. `robocopy` is the one to remember for copying large trees reliably.
- **Disk and system repair:** `chkdsk`, `sfc /scannow`, `diskpart`, `format`, `defrag`.
- **Management:** `gpupdate`, `gpresult`, `shutdown`, `tasklist`, `taskkill`,
  `services.msc`, `regedit`.

The pattern: a GUI exists for every one of these, and the command line is faster, scriptable,
and available when the GUI will not start. In a question, the command-line answer is
usually the right one when it is the only path that works in a broken environment.

## Windows settings and networking features

The settings categories the exam names: display and personalization, network and internet,
power (including sleep and the **power plan**), users and accounts (local versus Microsoft
account), time and language, accessibility, privacy, and **Windows Firewall** with its rule
sets.

For networking, the distinction that matters: a **workgroup** is a peer-to-peer arrangement
where each machine has its own accounts; a **domain** is centrally managed, with accounts
and policy from a directory service. **Shared folders**, **mapped drives** and **shared
printers** work in both, with different credential behavior. A machine that cannot see a
share is usually a network-profile problem (public versus private), a credential problem,
or a firewall rule — in that order.

## macOS and Linux

You are not expected to administer these, but you are expected to recognize them.

**macOS:** **Finder** for files, the **Dock** for running applications, **Mission Control**
for windows and spaces, **Time Machine** for backup, **Keychain** for credentials, **Disk
Utility** for disks and permissions, **Terminal** for the UNIX command line, and **APFS**
as the file system. Applications arrive as disk images or from the App Store, and the
security model is Gatekeeper: unsigned software does not run by default.

**Linux:** a shell (usually bash), a case-sensitive file system (**ext4** commonly), a
package manager (**apt**, **dnf**, **pacman** depending on distribution), permissions in
the classic owner/group/other model, **sudo** for elevation, and **systemd** with
`systemctl` for services. The desktop environment (GNOME, KDE) is separate from the
operating system, which is a distinction Windows does not have.

## Applications and cloud productivity

Installing software has requirements, and the requirements are the exam: architecture
(**32-bit versus 64-bit**), memory and disk, the OS version, and sometimes a specific
runtime or a license. Distribution methods are a download, a package, a network share, or
a **cloud-based productivity suite** used through a browser. A cloud application changes
the support question: there is nothing to install locally, the data lives in the service,
and the failure modes are account, network and browser rather than driver and disk.
