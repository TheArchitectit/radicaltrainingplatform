# Nutanix Cloud Infrastructure: Components and Use Cases (S1.1)

*Module S1.1 — Nutanix NCA 7.5 study track. Independent study material — see the disclaimer at the end.*

This lesson builds one mental picture: what a Nutanix Cloud Infrastructure (NCI) cluster is made of, what each of its three main names refers to, and where the whole thing sits compared with the storage-and-servers arrangement it replaces. Nothing here asks you to operate a cluster yet. The goal is recognition — you should finish able to hear a sentence about a Nutanix environment and know which part of the picture it is describing.

## One machine, three jobs

A traditional data centre keeps three things in three places: **servers** do the computing, a **network** connects everything, and a separate **storage array** holds the data. Adding capacity means buying the specific box that ran out.

Nutanix folds all three onto the same physical servers. Each server in a cluster contributes its CPU and memory to run workloads, its local disks to a shared pool of storage, and its network links to a fabric that ties the cluster together. The word for this is **hyperconverged**: the same nodes provide compute, storage, and the software that coordinates them.

That is the single most important idea in this lesson. Everything else — the product names, the size words — is detail layered on top of it.

## AOS, AHV, and Prism

Three names come up constantly. Keep them separate in your head:

- **AOS (Acropolis Operating System)** — the distributed software layer that turns a group of servers into one storage system. It pools the disks across nodes, decides where data lives, makes copies for protection, and moves data away from a node that needs maintenance. When people say "the cluster's storage", they usually mean AOS.
- **AHV (Acropolis Hypervisor)** — the hypervisor that runs virtual machines. A hypervisor is the layer that lets many virtual machines share one physical server safely. AHV is Nutanix's own; a cluster can also run other hypervisors, but AHV is the one the NCA material is built around.
- **Prism** — the management interface. Prism is where you look at health, run tasks, and configure the cluster. It comes in two scopes: **Prism Element**, which manages one cluster, and **Prism Central**, which manages many clusters together and adds cross-cluster features.

A useful shorthand: AOS is the storage brain, AHV runs the workloads, Prism is the window you look through.

## Node, block, and cluster

Three words describe how much hardware you have:

- A **node** is one physical server in the group. In Nutanix terms it is also called a host, and each node runs a small controller virtual machine that participates in the shared storage layer.
- A **block** is a chassis that holds several nodes and their disks. Blocks are how Nutanix sells and racks capacity in units, though the software treats the whole thing as one system.
- A **cluster** is the set of nodes that work together as a single system, with one shared pool of storage and one place to manage it. A cluster is the unit you administer.

The minimum practical cluster is small — as few as three nodes for a standard configuration, with special arrangements for two-node and single-node cases. You do not need the sizing rules yet; you need the vocabulary.

## Where NCI fits

NCI is the infrastructure layer: the compute, storage, and virtualisation foundation that applications run on. Two things follow from that.

First, NCI is **not** the applications. A database service, a container platform, or a file-sharing product may run *on* NCI, but they are separate products. Section 1.2 of this track is about recognising those neighbours.

Second, the pitch is operational rather than a single feature. The argument for hyperconverged infrastructure is that you buy one kind of building block, grow it in a straight line, and manage compute and storage from one place instead of three. That is why the conversation usually starts with a *situation* — a small team, a branch office, an ageing array — rather than with a specification.

## Worked example: matching three businesses to the pitch

Read each case and decide what the NCI conversation would be about. The point is the reasoning, not a product name.

1. **A 40-person accounting firm.** Two ageing servers and a storage array that is nearly full. No dedicated IT staff. *The fit is simplicity:* one cluster, one management interface, growth by adding a node. The pitch is "fewer things to run", not raw performance.
2. **A retail chain with a system in every store.** Each store runs a handful of virtual machines locally and needs to keep working when the link to head office drops. *The fit is small-footprint resilience:* a very small cluster per site, managed centrally alongside the others. The pitch is "many small sites, one pane of glass".
3. **A software team that needs capacity on demand.** They spin environments up and down and are tired of waiting on storage provisioning. *The fit is elastic pooling:* storage is drawn from a shared pool rather than carved from an array in advance. The pitch is "provisioning stops being a project".

If you can say *why* each case lands on a different part of the story, you have the recognition skill this objective asks for.
