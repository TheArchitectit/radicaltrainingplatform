# The Toolbox: Seven Names to Recognise (S1.3)

*Module S1.3 — Nutanix NCA 7.5 study track. Independent study material — see the disclaimer at the end.*

This lesson is a recognition drill. Seven tools come up whenever someone talks about running a Nutanix environment, and each one answers a different question. The exam objective is to hear a problem and name the tool, so this lesson is organised as *question → tool*, not as a feature tour.

## Move — "we are migrating"

**Move** handles migration: bringing workloads onto a Nutanix cluster from elsewhere, or moving them between clusters. It plans and runs the transfer of virtual machines, including from another hypervisor or another vendor's platform, and it can keep the source running until you are ready to cut over.

Listen for **migrate, move workloads, cut over, leave the old platform**. The distinguishing word is *from somewhere else*. Moving a VM between nodes in the same cluster is ordinary cluster operation, not a Move job.

## NGT — "the guest needs to cooperate"

**Nutanix Guest Tools (NGT)** is a small package installed *inside* a virtual machine. Without it, the cluster can still protect the VM with snapshots, but the guest operating system has no way to prepare for them. With NGT installed, the guest can quiesce its filesystem and applications so a snapshot is consistent, and the guest gains self-service restore.

The tell is a phrase about **the guest operating system** or about **application-consistent snapshots**. NGT is the tool you install on the machine being protected, not on the cluster.

## Foundation — "the hardware is bare"

**Foundation** is the imaging tool. It takes a brand-new, factory-fresh node and installs the hypervisor and AOS onto it, so it can join a cluster. It is used at the very beginning of a node's life, or when a node has to be rebuilt.

Listen for **new node, bare metal, image the host, reimage**. If the question says the node has no operating system yet, the answer is Foundation.

## Witness — "there is no majority"

A cluster normally decides who is in charge by majority vote among its nodes. Two-node clusters have no majority to appeal to, and a stretched cluster spanning two sites has a similar problem: if the link between sites breaks, each side must not decide on its own that it is the survivor, because both sides might then write to the same data.

**Witness** is a lightweight third party that provides that deciding vote. It runs somewhere outside the two nodes — typically a small virtual machine on a third site or in a public cloud — and it only participates when the cluster cannot reach a conclusion itself.

Listen for **two-node cluster, stretch cluster, split brain, arbitration, tie-breaker**.

## SSR — "the user deleted a file"

**Self-Service Restore (SSR)** lets a user restore individual files from a snapshot without opening a ticket and without an administrator mounting the snapshot for them. It works from inside the guest operating system, which is why it depends on NGT being installed.

The tell is **a single file or folder**, restored **by the user**, from **an existing snapshot**. Restoring a whole virtual machine is a different job.

## X-Ray — "will this design work?"

**X-Ray** tests a planned cluster configuration. Rather than discovering a problem during a real rollout, you describe the configuration you intend to build and X-Ray exercises it in a controlled way, reporting what passed and what did not.

Listen for **validate a design, test a configuration, will this work before we build it**. X-Ray is about a *plan*, not about a running production cluster's day-to-day health.

## Collector — "we need a picture of this environment"

**Collector** gathers inventory and configuration information from an environment and packages it into a report. It is commonly the first step when working with support, because it produces a consistent snapshot of what is actually deployed rather than a description assembled from memory.

Listen for **inventory, gather configuration, produce a report, before opening a case**.

## Worked example: question → tool

Match each statement to one tool, and say why the others do not fit.

1. "We are leaving a different hypervisor and want our virtual machines on Nutanix." — **Move.** Workloads are coming from another platform.
2. "A user needs last Tuesday's version of one spreadsheet." — **SSR.** A single file, restored by the user, from a snapshot.
3. "Two nodes, one site, and we must survive losing either node." — **Witness.** Two nodes have no majority; something outside must break the tie.
4. "The new node arrived with nothing on it." — **Foundation.** Bare hardware needs imaging.
5. "Before we buy, will this cluster layout actually behave?" — **X-Ray.** A design is being tested, not a live cluster.
6. "Support asked for a full picture of our configuration." — **Collector.** Inventory, packaged for a case.
7. "Snapshots of this database are not consistent." — **NGT.** The guest must be able to prepare itself.

Notice that three of the seven answers hinge on a single word: *from elsewhere* (Move), *by the user* (SSR), *before we build it* (X-Ray). That is the level of precision the exam expects.
