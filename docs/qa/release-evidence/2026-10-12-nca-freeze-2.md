### Reproducing the total

`run_freeze_chain.sh --expect-sha` compares the **working tree's HEAD** to the
SHA you name, so it must be run with that SHA checked out. The first record
printed the bare command, which fails from any later commit — including its own,
since the record was committed on top of the head it names. Stated properly:

```bash
git checkout 0e12fcd62eaad85a377daa0b47e9d71413ad2dc3
bash tests/gates/run_freeze_chain.sh --log /tmp/freeze.log \
  --expect-sha 0e12fcd62eaad85a377daa0b47e9d71413ad2dc3
```

`run_freeze_chain.sh` runs the same commands, in the same order, as
`.github/workflows/build.yml` and `pwa-deploy.yml`, prints one PASS/FAIL per
gate and an `N/N at <sha>` total, and refuses to report a total measured at a
different commit than the one named. A pasted transcript cannot be re-run; this
can.

**Freeze means no content edits afterward without a new head record.**
